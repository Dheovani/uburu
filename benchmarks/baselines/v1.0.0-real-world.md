# Uburu 1.0 real-world performance baseline

This baseline consolidates privacy-safe Release measurements from the same AMD Ryzen 9 5950X workstation with approximately 32 GiB of memory. It complements the deterministic Google Benchmark guardrails in `reference-developer.json`; it does not replace them because the private real-world corpus is unavailable to CI.

## Document corpus

The corpus contains approximately 7.35 GiB across 216 to 217 PDF files. Searches used the same known exact phrase, recursive traversal, binary inclusion, a 256 MiB per-file limit, a 512 MiB memory budget, and automatic worker selection.

| Platform | Strategy | Matches | Files | Total | Files/s | Bytes/s | Result memory |

| Windows | Direct | 1 | 217 | 11.209 s | 19 | 655,896,312 | 467 B |
| Windows | Indexed | 1 | 0 | 9.044 s | 0 | 0 | 467 B |
| Windows | Hybrid | 1 | 217 | 21.294 s | 10 | 345,256,023 | 467 B |
| Linux | Direct | 1 | 216 | 7.053 s | 30 | 1,042,099,710 | 453 B |
| Linux | Indexed | 1 | 0 | 4.340 s | 0 | 0 | 453 B |

Initial indexing processed 217 entries on Windows and 216 on Linux. The observed peak indexing working memory was approximately 356 MB on Windows and 429 MB on Linux, both below the configured 512 MiB budget. The unchanged incremental pass reused every catalog entry on both platforms.

## Code repository

The formal Linux Release run over 268 source and documentation files produced 3,709 matching occurrences. Direct, indexed, and hybrid totals were 80 ms, 32 ms, and 118 ms respectively. Initial indexing completed without failures, and the incremental pass reused all 268 catalog entries.

The earlier Windows workflow run over 247 files completed direct, indexed, and hybrid search in 1.760 s, 802 ms, and 3.307 s. It used a different preliminary commit and is retained as directional evidence rather than a strict cross-platform comparison.

## Regression interpretation

A future comparable run requires investigation when any of the following occurs without a documented dataset or environment change:

- direct, indexed, or hybrid total time exceeds twice the applicable platform value;
- a strategy loses the known match or strategies disagree on the final result set;
- an unchanged incremental pass does not reuse every eligible catalog entry;
- indexing exceeds the configured 512 MiB working-memory budget;
- cancellation exceeds the documented two-second release bound;
- extraction failures increase without newly added hostile, protected, or unsupported documents.

The source measurements and exact artifact metadata are preserved in `docs/releases/v1.0.0-windows-document-corpus.md`, `docs/releases/v1.0.0-linux-document-corpus.md`, `docs/releases/v1.0.0-linux-uburu-repository.md`, and `docs/releases/v1.0.0-preliminary-windows-code.md`.
