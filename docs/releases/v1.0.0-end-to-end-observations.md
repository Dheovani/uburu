# Uburu 1.0 end-to-end observations

This record combines the Windows and Linux recordings with the formal aggregate validation reports. It covers the product-level behavior that deterministic microbenchmarks cannot observe.

| Area | Windows | Linux | Decision |
| --- | --- | --- | --- |
| Packaged startup | Installed application launched from the Windows shortcut | AppImage launched outside the build tree | Passed |
| Exact document search | Known phrase found in the selected PDF scope | Same phrase found in the selected PDF scope | Passed |
| Progressive results | UI remained usable while the multi-gigabyte corpus was scanned | Results appeared without blocking window interaction | Passed |
| Cancellation | Search and indexing accepted cancellation; subsequent search remained usable | Search/index interaction remained responsive after cancellation | Passed |
| Preview | A section-formatting defect was found, fixed, and covered by a multi-page regression test | Corrected occurrence-aware preview was validated | Passed after remediation |
| Persistence | Scope and recent-path state survived application restart | AppImage state remained usable across restart | Passed |
| Indexing | Progress was visible; cancellation preserved direct search; formal rebuild ended fresh | Formal rebuild ended fresh and incremental reuse covered every entry | Passed |
| Memory | Formal indexing remained below the 512 MiB configured budget | Formal indexing remained below the 512 MiB configured budget | Passed |
| Removal/portability | Windows uninstall removed the program entry and shortcut | AppImage required no installation and launched from its packaged artifact | Passed |

Linux was materially faster in the observed PDF-corpus and code-repository runs. The measurements establish a baseline but do not isolate the cause; future optimization work must profile filesystem traversal, compiler/runtime differences, PDF extraction, SQLite, and scheduling before changing architecture.

No unexplained crash, assertion, out-of-scope result, stale final result, unbounded memory condition, or interface freeze remains open from this validation cycle.
