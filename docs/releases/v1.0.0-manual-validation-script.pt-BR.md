# Roteiro final de validação manual do Uburu 1.0.0

Este é o roteiro mínimo para encerrar a validação manual da versão 1.0.0. São necessárias somente três gravações contínuas. Não é necessário narrar: basta deixar visíveis os comandos, as ações e os resultados. Se um passo falhar, interrompa a gravação e anote o timestamp; não tente esconder ou contornar a falha.

Antes de começar, use o mesmo commit limpo nas três gravações. Mostre o hash do commit no início de cada vídeo. Não publique nos documentos do projeto nomes de arquivos privados, expressões privadas diferentes da frase de validação já escolhida ou conteúdo pessoal exibido no preview.

## Evidências a entregar

| Arquivo sugerido | Ambiente | Duração estimada | Objetivo |
| --- | --- | ---: | --- |
| `uburu-v1-windows-desktop.mp4` | Windows | 10–15 min | Instalação, pesquisa real, preview, responsividade, cancelamento, indexação e reinício |
| `uburu-v1-git-cli.mp4` | Windows ou Linux | 8–12 min | Estado Git, índice incremental, branch, detached HEAD e worktree sem tocar no repositório original |
| `uburu-v1-linux-appimage.mp4` | Linux | 10–15 min | AppImage, pesquisa real, preview, cancelamento, integração com o desktop e persistência |

Depois das gravações, preencha somente a tabela de resultado no fim deste arquivo e forneça o caminho ou link dos três vídeos. Os relatórios automáticos, hashes, benchmarks e atualização final do `TODO.md` continuam sendo responsabilidade do desenvolvimento.

## Gravação 1 — Windows desktop e instalador

### Preparação

1. Inicie a gravação antes de executar qualquer comando.
2. Em um PowerShell aberto na raiz do Uburu, mostre:

```powershell
git status --short
git rev-parse HEAD
Get-FileHash .\dist\windows-msvc-release\installer\uburu-setup-*-windows-x64.exe -Algorithm SHA256
```

3. `git status --short` deve ficar vazio. Se houver mais de um instalador, use explicitamente o instalador produzido para o release candidate.
4. Instale o Uburu. Confirme que o aplicativo abre pelo atalho criado pelo instalador.

### Pesquisa e preview no corpus real

1. Selecione `C:\Users\dheov\Documents\Leituras` como escopo.
2. Informe `pdf` no filtro de tipos.
3. Ative inclusão de binários e subdiretórios.
4. Pesquise exatamente:

```text
A apreensão de uma verdade científica passa, normalmente, por vários estágios de certeza
```

5. Aguarde a conclusão e mostre as métricas da interface.
6. Abra o resultado e mostre que o preview foi deslocado para a ocorrência correta.
7. O teste passa se houver pelo menos uma ocorrência, nenhum resultado estiver fora do escopo, o preview mostrar a frase correta e arquivos problemáticos não encerrarem a pesquisa.

### Responsividade e cancelamento da pesquisa

1. Inicie uma pesquisa ampla por `a` no mesmo corpus.
2. Enquanto ela estiver ativa, mova e redimensione a janela, abra e feche um menu e role os painéis. A interface não pode congelar.
3. Clique em `Cancelar` enquanto a barra de progresso estiver ativa.
4. O estado de cancelamento deve aparecer prontamente, a barra deve parar e resultados atrasados não podem alterar uma pesquisa posterior.
5. Repita a pesquisa exata anterior. Ela deve continuar funcionando após o cancelamento.

### Indexação, cancelamento e recuperação

1. Use `Search > Reindexar escopo` ou `Ctrl+Alt+I`.
2. Aguarde a barra de indexação avançar e use `Search > Cancelar indexação` ou `Ctrl+Alt+Esc`.
3. Confirme que a aplicação permanece utilizável e que uma pesquisa direta ainda funciona.
4. Inicie a reindexação novamente e permita que ela termine.
5. Feche e abra o Uburu. Confirme que o escopo, histórico e preferências continuam disponíveis e que a pesquisa exata ainda retorna o resultado.

### Remoção

1. Feche o Uburu e desinstale-o pelo Windows.
2. Confirme que o diretório do programa foi removido.
3. Não apague manualmente os dados do usuário: a preservação de preferências e índice durante a desinstalação é intencional.

## Gravação 2 — Git e CLI em clone descartável

Esta gravação usa um clone temporário. Não faça alterações no repositório original. Substitua `<UBURU_CLI>` pelo caminho absoluto do `uburu.exe` Release e `<UBURU_ORIGINAL>` pelo caminho absoluto do repositório original.

### Preparação e índice inicial

```powershell
$cli = "<UBURU_CLI>"
$source = "<UBURU_ORIGINAL>"
$root = Join-Path $env:TEMP "uburu-v1-git-validation"
$worktree = Join-Path $env:TEMP "uburu-v1-worktree-validation"
$validationId = [guid]::NewGuid().ToString("N")
$modifiedToken = "UBURU_V1_MODIFIED_$validationId"
$untrackedToken = "UBURU_V1_UNTRACKED_$validationId"
$ignoredToken = "UBURU_V1_IGNORED_$validationId"
$branchToken = "UBURU_V1_BRANCH_$validationId"
$primaryOnlyToken = "UBURU_V1_PRIMARY_ONLY_$validationId"
$worktreeOnlyToken = "UBURU_V1_WORKTREE_ONLY_$validationId"

if (Test-Path -LiteralPath $root) { Remove-Item -LiteralPath $root -Recurse -Force }
if (Test-Path -LiteralPath $worktree) { Remove-Item -LiteralPath $worktree -Recurse -Force }

git clone --local $source $root
Set-Location $root
git config user.name "Uburu Validation"
git config user.email "validation@uburu.local"
Add-Content .git/info/exclude "`n.uburu-cli/"
git status --short
git rev-parse HEAD
& $cli index-rebuild . --types cpp,hpp,qml,md,txt --format jsonl
& $cli index-status . --format jsonl
```

O índice inicial deve terminar sem cancelamento ou corrupção e `index-status` deve informar estado fresco.

### Arquivos modificados, adicionados, removidos e ignorados

```powershell
git switch -c validation/working-tree
Add-Content README.md "`n$modifiedToken"
Set-Content validation-untracked.txt $untrackedToken
New-Item -ItemType Directory -Path validation-ignored | Out-Null
Set-Content validation-ignored/ignored.txt $ignoredToken
Add-Content .gitignore "`nvalidation-ignored/"
git rm docs/product/cli.md
git status --short --ignored

& $cli index-rebuild . --types cpp,hpp,qml,md,txt --format jsonl
& $cli search . $modifiedToken --strategy hybrid --types md --format jsonl
& $cli search . $untrackedToken --strategy hybrid --types txt --format jsonl
& $cli search . $ignoredToken --strategy direct --types txt --format jsonl
```

Os tokens modificado e não rastreado devem ser encontrados. O token ignorado não deve ser encontrado enquanto `.gitignore` estiver ativo. O arquivo removido não pode aparecer como resultado obsoleto.

### Branch, detached HEAD e worktree

```powershell
git add -A
git commit -m "test: prepare disposable validation state"
git switch -c validation/alternate
Set-Content validation-branch.txt $branchToken
git add validation-branch.txt
git commit -m "test: add alternate branch token"

& $cli index-rebuild . --types cpp,hpp,qml,md,txt --format jsonl
& $cli search . $branchToken --strategy hybrid --types txt --format jsonl

$alternateCommit = git rev-parse HEAD
git switch --detach HEAD~1
& $cli index-rebuild . --types cpp,hpp,qml,md,txt --format jsonl
& $cli search . $branchToken --strategy hybrid --types txt --format jsonl

git switch validation/alternate
git worktree add $worktree $alternateCommit
Set-Location $worktree
& $cli index-rebuild . --types cpp,hpp,qml,md,txt --format jsonl
& $cli search . $branchToken --strategy hybrid --types txt --format jsonl

Set-Content validation-worktree-only.txt $worktreeOnlyToken
& $cli index-rebuild . --types txt --format jsonl
& $cli search . $worktreeOnlyToken --strategy hybrid --types txt --format jsonl

Set-Location $root
& $cli search . $worktreeOnlyToken --strategy hybrid --types txt --format jsonl
Set-Content validation-primary-only.txt $primaryOnlyToken
& $cli index-rebuild . --types txt --format jsonl
& $cli search . $primaryOnlyToken --strategy hybrid --types txt --format jsonl

Set-Location $worktree
& $cli search . $primaryOnlyToken --strategy hybrid --types txt --format jsonl
```

Na branch alternativa e no worktree, o token deve ser encontrado. No commit anterior em detached HEAD, ele não deve ser encontrado. Os tokens exclusivos devem ser encontrados somente no diretório em que foram criados; as buscas cruzadas devem terminar com zero ocorrências e código `1`, comprovando que o índice de um diretório não vazou resultados para o outro.

Ao terminar, encerre a gravação. O clone e o worktree são descartáveis e podem ser removidos posteriormente.

## Gravação 3 — Linux AppImage

### Artefato e inicialização

1. Inicie a gravação e mostre:

```sh
git status --short
git rev-parse HEAD
cd dist/linux-appimage
sha256sum -c uburu-linux-x86_64.AppImage.sha256
chmod +x uburu-linux-x86_64.AppImage
./uburu-linux-x86_64.AppImage
```

2. Se a máquina não possuir FUSE 2, use:

```sh
APPIMAGE_EXTRACT_AND_RUN=1 ./uburu-linux-x86_64.AppImage
```

3. O AppImage deve abrir fora da árvore de build, sem bibliotecas ausentes.

### Pesquisa, preview e integração com o desktop

1. Se a partição Windows estiver montada, selecione `/mnt/c/Users/dheov/Documents/Leituras`. Caso contrário, use uma cópia acessível do mesmo corpus.
2. Configure `pdf`, inclusão de binários e subdiretórios.
3. Execute a mesma frase exata usada no Windows.
4. Confirme pelo menos uma ocorrência, escopo correto e preview posicionado na frase.
5. No menu de ações de um resultado, teste `Abrir arquivo` e `Abrir local do arquivo`. O aplicativo padrão e o gerenciador de arquivos devem abrir corretamente.
6. Inicie uma pesquisa ampla por `a`, interaja com a janela e cancele. A interface não pode congelar nem publicar resultados atrasados depois do cancelamento.
7. Inicie uma indexação, cancele-a, confirme que a aplicação continua utilizável e execute novamente a pesquisa exata.
8. Feche e abra o AppImage. Confirme que escopo, histórico e preferências foram preservados.

### Evidência automática Linux

Com o AppImage fechado, ainda na gravação, execute a validação agregada usando o CLI Release:

```sh
cmake \
  -DUBURU_EXECUTABLE:FILEPATH="$PWD/../../build/linux-release/apps/cli/uburu" \
  -DUBURU_DATASET_ROOT:PATH="/mnt/c/Users/dheov/Documents/Leituras" \
  -DUBURU_EXPRESSION:STRING="A apreensão de uma verdade científica passa, normalmente, por vários estágios de certeza" \
  -DUBURU_DATASET_ID:STRING=linux-pdf-corpus-formal \
  -DUBURU_DATASET_PROFILE:STRING=document-corpus \
  -DUBURU_CONFIGURATION:STRING=linux-release \
  -DUBURU_OUTPUT:FILEPATH="$PWD/../../docs/releases/v1.0.0-linux-document-corpus.md" \
  -DUBURU_TYPES:STRING=pdf \
  -DUBURU_INCLUDE_BINARY:BOOL=ON \
  -DUBURU_INCLUDE_SUBDIRECTORIES:BOOL=ON \
  -DUBURU_ALLOW_PARTIAL_FAILURE:BOOL=ON \
  -DUBURU_MINIMUM_MATCHES:STRING=1 \
  -DUBURU_MAX_SIZE_MIB:STRING=256 \
  -DUBURU_MEMORY_BUDGET_MIB:STRING=512 \
  -DUBURU_THREADS:STRING=auto \
  -P "$PWD/../../scripts/run-product-validation.cmake"
```

O comando deve terminar com `Sanitized validation evidence written` e o relatório deve indicar `Status: Passed`. Se o corpus estiver em outro ponto de montagem, altere apenas `UBURU_DATASET_ROOT`.

## Critérios finais de aprovação

A validação manual termina quando:

- nenhuma gravação contém crash, assertion, congelamento ou resultado fora do escopo;
- Windows e Linux encontram a frase conhecida no corpus;
- o preview abre na ocorrência correta;
- pesquisa e indexação podem ser canceladas e o aplicativo continua utilizável;
- não aparecem resultados atrasados de uma operação cancelada;
- indexação concluída continua pesquisável após reiniciar;
- branch, detached HEAD e worktree não vazam estado entre si;
- instalador Windows e AppImage Linux iniciam a aplicação empacotada;
- o relatório automático Linux termina como `Passed`.

Não é necessário gravar novamente testes unitários, Werror, format-check, benchmarks determinísticos, SBOM ou checksums internos: esses são gates automatizados.
